# Plan — Adaptador de Claude Code

## Objetivo

Añadir el adaptador de runtime **Claude Code** al CLI `rei`, reutilizando la
infraestructura de adaptadores existente, y documentar **Cursor** y **Codex**
como runtimes sin subagentes nativos (funcionan por *fallback*, sin
configuración).

Resultado esperado:

- `rei init claude` genera `.claude/agents/<rol>.md` a partir del `## Contrato`
  de cada rol, con frontmatter nativo de Claude Code (`name`, `description`,
  `tools`, `model` opcional), la marca `GENERATED` y sin sobrescribir archivos
  sin marca.
- `rei init claude --check` verifica sin escribir y sale 0 si todo coincide.
- `.rei/adapters/claude/` contiene la plantilla y el mapa de herramientas.
- `rei init`, `rei init opencode`, `rei init opencode --check` y
  `rei init status` conservan su comportamiento.
- `rei help init` y `.rei/docs/harness/adapters.md` documentan Claude Code y el
  fallback Cursor/Codex.

## Cambios

### 1. Generalizar `internal/adapter` por runtime

Extraer un descriptor de runtime y funciones genéricas para no duplicar la
lógica de extracción de `## Contrato`, marca `GENERATED`, idempotencia y no
sobrescritura.

- `runtime`: `name` (`opencode`/`claude`), `hostedDir`
  (`.opencode/agents`/`.claude/agents`), `mark`, `nativeKey` (`permission` para
  OpenCode, `tools` para Claude), `validTargets` (claves válidas del runtime) y
  un builder de datos de plantilla.
- `toolEntry` pasa a `map[string][]string` (una entrada por herramienta
  genérica con su clave nativa). `loadToolMap(p, rt)` lee
  `.rei/adapters/<rt.name>/tools.json`, exige cobertura de todas las
  herramientas genéricas, valida cada destino contra `rt.validTargets` y extrae
  los destinos con `rt.nativeKey`. **No se modifica**
  `.rei/adapters/opencode/tools.json`: su esquema (`permission`) se sigue
  leyendo igual.
- `resolveTargets(tools, tm, rt)`: aplana las herramientas del rol en orden de
  declaración, deduplicando destinos.
- `renderAgent(p, rt, role)`: carga `<rt.name>/agent.tmpl` y la ejecuta con los
  datos que produce el builder del runtime.
- `generateAll`/`check`/`install`: versión genérica; `install` imprime
  `== rei init <runtime> ==` y reutiliza `InstallSkeleton` + `EnsureStructure`.
- Wrappers exportados: `Install`/`Check` (OpenCode, firma actual intacta) y
  `InstallClaude`/`CheckClaude`.
- Reutilizar `readRole`, `ParseRole`, `ExtractContract`, `agentPath` y la lógica
  de marca/`[WARN]`/`[OK]`/`[UPD]`/`[FAIL]` existentes.

### 2. Plantilla y mapa de Claude

`.rei/adapters/claude/agent.tmpl`:

```text
---
name: {{.Name}}
description: {{.Description}}
tools: {{.Tools}}
{{if .Model}}model: {{.Model}}
{{end}}---

{{.Mark}}

{{.Contract}}
```

`.rei/adapters/claude/tools.json` (clave nativa `tools`):

```json
{
  "read":     { "tools": ["Read"] },
  "write":    { "tools": ["Write", "Edit"] },
  "edit":     { "tools": ["Write", "Edit"] },
  "search":   { "tools": ["Grep", "Glob"] },
  "shell":    { "tools": ["Bash"] },
  "subagent": { "tools": ["Agent"] }
}
```

Mapeo genérica → nativa: `read→Read`; `write`/`edit→Write, Edit`;
`search→Grep, Glob`; `shell→Bash`; `subagent→Agent`. El frontmatter `tools` es
una lista separada por comas, en el orden de declaración del rol y sin
duplicados. `model` se emite solo si el rol lo declara (pass-through).

Marca de Claude:
`<!-- GENERATED by rei — no editar; regenerar con \`rei init claude\` -->`.

### 3. CLI `rei init claude [--check]`

- `cmdInit` añade `len(args)==1 && args[0]=="claude"` →
  `adapter.InstallClaude(p, os.Stdout)` y
  `len(args)==2 && args[0]=="claude" && args[1]=="--check"` →
  `adapter.CheckClaude(p, os.Stdout)`.
- Texto de uso: `rei init [status|opencode|claude [--check]]`.

## Restricciones

- No implementar adaptadores nativos para Cursor ni Codex (solo documentar el
  fallback).
- No modificar el formato canónico de rol ni `.rei/agents/*`.
- No modificar `.rei/adapters/opencode/tools.json`; su comportamiento se
  mantiene.
- Sin dependencias externas: solo la biblioteca estándar.
- La marca `GENERATED` es lo único que autoriza la sobrescritura; un archivo sin
  marca se conserva y se avisa (`[WARN]`).
- `--check` no escribe.
- `rei init`, `rei init opencode`, `rei init opencode --check` y
  `rei init status` deben seguir funcionando igual.
- `gofmt`/`go vet` y `make test` deben pasar.
